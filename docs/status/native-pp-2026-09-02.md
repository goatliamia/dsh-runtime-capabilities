# 状态：DSH 原生 Progress / Effect Projection 实验（2026-09-02）

设计：`docs/16-native-pp-experiment.md` | Event 语义对照表：`docs/16-native-pp/event-semantics.{md,json}` | 原始结果：`experiments/native-pp/results/`

## 0. 结论摘要

1. **Progress / Effect 在 DSH 中是原生 Primitive，不是 Policy**：`session/event` firehose + durable `session.jsonl.zstd` + `goal/change` 记录已完整表达执行/效果/进度语义；一个纯 fold 即可投影全部 verdict，且 live 折叠、官方跨进程重放、独立实现三路逐字段一致。
2. **ProgressContract 只提供统一 projection**（如实报告）：无需任何新 primitive；其价值 = 统一形状（`axes.execution / axes.goal / axes.effect`、`verdict`、`unknownFields`、每条 effect 带 `support` 记录引用）。
3. **execution / effect 双轴正交实测成立**：`toolfail` 场景 turn=completed 而 execution=failed、effect=failed——运行结果与执行效果互不解释。
4. **观察不到的 effect 诚实返回 unknown 且 unknown 就是正确答案**：`unobservable` 场景世界真值 effectFileExists=true，投影 worldEffect=unknown（support=[]）——不伪造确定性。
5. **零成本面实测**：A/B 臂工具面逐位相等、modelCalls 相等、payload 差 90 字符；投影自身零模型流量，host 成本 ≈ 1.9–2.3 μs/事件。
6. **修正发现（入账 E3 对照表）**：本版 DSH 中 thrown tool 的错误信号在 `tool/result.data.message.content[].isError:true`，`data.error` 保持缺省（E3 表原文「error 来自 result.error.info」需按实机修订）。

## 4. E3 Event 语义对照（只读源码，零运行）

- `goal/change`：operation=create|edit|pause|resume|complete|block|clear；phase=active|paused|blocked|complete；disarmed 是 GoalActivation（进程本地不持久化）；latest-wins 折叠。

## 8. 四象限

横轴=Effect 可观察性，纵轴=Execution 可观察性：

| | Effect 可观察 | Effect 不可观察 |
|---|---|---|
| **Execution 可观察** | **Q1 支持（实测）**：投影==真值（ok、toolfail） | **Q2 支持且 verdict=unknown（实测）**：诚实未知（unobservable） |
| **Execution 不可观察** | Q3 不支持（推导）：无执行事实可投影，需新暴露 seam | Q4 不支持（推导）：双重不可观察 |

Q3/Q4 为推导结论（未实测）：要覆盖它们必须新增 execution 暴露机制——正是 `docs/14` 所述 runtime seam 的领地，与「Progress 是 Primitive」不冲突（seam 暴露事实，投影解释事实）。

## 9. 不确定项

1. goal 轴未被活场景实测（无 goal/change 记录）；fold 正确性由构造+重放一致保证，缺真实 goal 生命周期数据。
2. E5 N=1 且 agent 行为有方差：只能报「无系统性增量」方向，不能报「严格零 token 差」。
3. E3 表 21 行 uncertain（覆盖包之外/emit 点未定位/字段未完整读取）。
4. tool/result 错误形状实机修正（§0.6）待与上游源码双模型复核后回写 E3 表。
5. restore 构造器追加 session/end-seed（stored→restored +1）依赖官方语义；机制变化需重验。
6. 首轮运行的 harness 噪声（agent 试调不存在的 `write` 工具被拒、result.txt 跨格残留）已在 driver 修复；不影像判定。
7. 三场景各 N=1：verdict 声明对「实际发生的事件」成立（折叠语义），场景级统计外推不成立。

## 10. 可支持 / 不可支持结论

**可支持（本轮实测）**
- Progress/verdict 是 Event 流的纯投影：live fold == 官方跨进程重放 == 独立实现，三路一致；
- reload 后从持久化 log 重导出完全相同状态（官方 loadStored+prepare 路径）；
- execution/effect 双轴正交、unobservable→unknown、零 prompt/tool-schema/model-call 增量；
- goal/change（phase/revision/roundsStarted/operation 全 durable）作为持久化 Progress primitive（源码级）。

**不可支持**
- 事件流之外的 effect 无法被投影获知——Q2 的正确行为是 unknown，不是获得真值；
- execution 本身不可观察时（Q3/Q4），投影无从谈起，需要新的暴露 seam（runtime seam 领域），本轮不越界。

**对「ProgressContract 只提供统一 projection」的裁决**：**成立**。DSH 现有机制（session/event + durable log + goal/change + SessionStore/sessionPersistence）已完整表达语义；ProgressContract 的实现（`experiments/native-pp/projection/`）只是统一了形状与 unknown 规则，未引入任何新 primitive。
